# Project Management Planning – KantorIn

## Overview

This project is a Project Management Planning case study developed based on a simulated website development project for KantorIn, a startup focused on buying and renting office equipment.

The project simulates the role of a Project Manager in a software house and focuses on planning, structuring, scheduling, monitoring, and risk management for a website MVP development project.

The case study uses assumptions for project duration, budget, resources, and project metrics.

## Project Objectives

The main objective is to plan the development of a KantorIn website MVP that supports:

- Product browsing and catalog management
- Buying and renting office equipment
- User authentication
- Transaction management
- Admin management
- Testing and deployment

## Project Management Deliverables

### 1. Project Charter

The Project Charter defines the project's initial direction and boundaries, including:

- Project objectives
- Project scope
- Success metrics
- Project duration
- Budget assumption
- Required resources
- Project stakeholders
- Project outputs

### 2. Work Breakdown Structure (WBS)

The WBS breaks the project into structured deliverables and work packages:

- Initiation & Planning
- UI/UX Design
- Development
- Testing
- Deployment
- Closing

This structure helps organize project activities and clarify the work required to achieve each project deliverable.

### 3. Project Schedule

A project schedule was developed for an 8-week project timeline.

The schedule includes:

- Work packages
- Timeline
- Dependencies
- Project milestones
- Feature development
- Testing and UAT
- Deployment
- Documentation and handover

## Project Control

The planning process also includes basic project control mechanisms to support project monitoring.

### Scope Control

The project scope is used as a baseline to ensure that project activities remain aligned with the agreed requirements.

### Schedule Control

Project progress is compared with the planned schedule to identify potential delays and determine necessary adjustments.

### Performance Measurement

Project performance is monitored using milestones, progress tracking, deliverable completion, and project metrics.

### Communication & Reporting

Project updates are supported through:

- Weekly progress meetings
- Status reports
- Issue tracking
- Action items
- Stakeholder updates

## Risk Management

An initial risk register was developed to identify potential project risks and their mitigation strategies.

Key risks include:

- Requirement changes
- Development delays
- Critical bugs during UAT
- Resource availability
- Deployment issues

Each risk is considered based on its probability, impact, and mitigation or response strategy.

## Project Milestones

The project includes four major milestones:

- M1 — Requirements Approved
- M2 — Design Approved
- M3 — Feature Complete
- M4 — Go-Live
